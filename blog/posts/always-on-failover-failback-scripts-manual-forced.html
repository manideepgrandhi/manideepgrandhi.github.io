Always on Failover & Failback scripts (Manual & Forced)

alwayson

Planned Manual Failover Steps/DR Failover Testing

1. Connect to Primary Instance Name (Not to AlwaysON Listener) and execute below script

USE [master]
GO
ALTER AVAILABILITY GROUP [AOAG_FAIL]
MODIFY REPLICA ON N'IADB-PO-P01V1\POV1' WITH (AVAILABILITY_MODE = SYNCHRONOUS_COMMIT)
GO
ALTER AVAILABILITY GROUP [AOAG_FAIL]
MODIFY REPLICA ON N'IADB-AS-P01V1\ASV1' WITH (AVAILABILITY_MODE = SYNCHRONOUS_COMMIT)
GO

2. Verify DR database is in “Synchronized” state instead of “Synchronizing” State

3. Connect to DR instance and execute below script

USE [master]
ALTER AVAILABILITY GROUP [AOAG_FAIL] FAILOVER
GO

ALTER AVAILABILITY GROUP [AOAG_FAIL]
MODIFY REPLICA ON N'IADB-PO-P01V1\POV1' WITH (AVAILABILITY_MODE = ASYNCHRONOUS_COMMIT)
GO
ALTER AVAILABILITY GROUP [AOAG_FAIL]
MODIFY REPLICA ON N'IADB-AS-P01V1\ASV1' WITH (AVAILABILITY_MODE = ASYNCHRONOUS_COMMIT)
GO

######################################################################################################

Unplanned Failover/ Primary instance becomes inaccessible due to network or disk related issues

1. Execute below script in DR instance to bring the Listener and db online

ALTER AVAILABILITY GROUP [AOAG_FAIL] FORCE_FAILOVER_ALLOW_DATA_LOSS;

2. When primary instance comes online, execute below script on
ALTER DATABASE [XXXXX] SET HADR RESUME;
