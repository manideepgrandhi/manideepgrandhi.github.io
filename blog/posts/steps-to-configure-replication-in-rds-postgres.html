Steps to Configure Replication in RDS PostgreSQL

Configuring replication in Amazon RDS for PostgreSQL typically involves different steps depending on whether you're setting up Read Replicas (Streaming Replication) or Logical Replication.

1. Configuring Read Replicas (Streaming Replication)

Purpose: Read scaling and disaster recovery.

Prerequisites:

Existing RDS PostgreSQL DB instance (primary).

Steps:

Open the Amazon RDS Console
Go to AWS Management Console → RDS service.
Select Your Primary DB Instance
In "Databases," select your PostgreSQL DB instance.
Create Read Replica

Click "Actions" dropdown.

Choose "Create Read Replica."

Configure Replica Options

DB Instance Identifier: Unique name (e.g., my-postgres-replica-1)
Instance Class: Choose type (e.g., db.t3.medium)

Storage: Match or adjust

Multi-AZ Deployment: Optional, only if replica is critical

Networking: Match VPC, subnet, security groups with primary

Port: Usually 5432

Parameter/Option Groups: Default or custom
Encryption: Must match if primary is encrypted
Backup Retention: Set independently
Monitoring: Configure if needed
Create Replica
Review settings and click Create Read Replica.
What Happens Next
AWS provisions a new RDS instance, restores a snapshot from primary, starts WAL streaming.

Replica status shifts from Creating to Available.

Connecting

Find the new endpoint in RDS console for read operations.

Monitor ReplicationLag metric in CloudWatch.

2. Configuring Logical Replication

Purpose: Replicate specific tables or databases, ideal for cross-version upgrades or external replication.

Prerequisites:

RDS PostgreSQL DB instance (publisher)
PostgreSQL v10+
Target PostgreSQL instance (subscriber): RDS, EC2, or on-prem
A. Configure Publisher (Source RDS Instance)
DB Parameter Group Modification
In RDS console: Parameter groups → Create/modify group
Set params:
rds.logical_replication = 1
wal_sender_timeout = 60s
max_replication_slots, max_wal_senders (increase as needed)
Associate Parameter Group

In "Databases," select instance → Modify → Set to new parameter group → Apply and reboot.

Create Replication User
sql
CREATE USER my_replication_user WITH REPLICATION ENCRYPTED PASSWORD 'your_strong_password';
GRANT rds_replication TO my_replication_user;
Grant SELECT on published tables.
Create Publication
To publish all tables:
sql
CREATE PUBLICATION my_all_tables_pub FOR ALL TABLES;
Or for specific tables:
sql
CREATE PUBLICATION my_specific_tables_pub FOR TABLE table1, schema.table2;
B. Configure Subscriber (Target Instance)
Provision and Prepare Instance
Create target RDS/EC2 if needed.

Ensure schema and primary keys exist (logical replication does not replicate DDL).

Create Subscription
sql
CREATE SUBSCRIPTION my_subscription
  CONNECTION 'host=your_publisher_rds_endpoint.amazonaws.com dbname=your_database user=my_replication_user password=your_strong_password'
  PUBLICATION my_all_tables_pub;

Next Steps

Subscriber connects to publisher, performs initial sync, then streams and applies changes.

Monitoring

On publisher:
pg_replication_slots for slot status
pg_stat_replication for connection status
On subscriber:
pg_stat_subscription for subscription status
Use CloudWatch for metrics.

Important Notes:

DDL changes: Not automatically replicated. Apply to both sides.

Primary Keys: Required for updates and deletes.

Conflicts: Bi-directional/inserts require manual conflict management.

Permissions: Replication user needs correct grants.

Networking: Security groups must allow relevant port (5432) connectivity.
